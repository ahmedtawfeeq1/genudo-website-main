Introduction

The GenuDo API is organised around REST. It has predictable, resource-oriented URLs, returns JSON, and uses standard HTTP verbs and status codes. The base URL for all requests is:

BASEhttps://api.genudo.ai/v1
Everything you can do in the GenuDo dashboard, you can do over the API — create agents, connect channels, drive conversations and read analytics.

Authentication

Authenticate with a workspace API key sent as a Bearer token. Create and rotate keys in Settings → API keys. Keep keys server-side — never ship them in a browser.

cURL
# Every request carries your key as a Bearer token
curl https://api.genudo.ai/v1/agents \
  -H "Authorization: Bearer $GENUDO_API_KEY"

Errors & rate limits

GenuDo uses conventional HTTP status codes. 2xx means success, 4xx a problem with the request, and 5xx an error on our side. Errors return a JSON body with a machine-readable code and a human message.

JSON · 422
{
  "error": {
    "code": "validation_error",
    "message": "channel is required",
    "param": "channel"
  }
}

The API is rate limited per workspace. Limits are returned on every response in the X-RateLimit-Remaining header; a 429 means you should back off and retry with exponential delay.

Agents

An agent is a configured AI employee: a persona, a knowledge base, a set of tools and a model routing policy. Create one, then deploy it to any channel.

POST/v1/agents
GET/v1/agents/{id}
ParameterTypeDescription
namestringDisplay name for the agent, e.g. “Sales Agent”.
personastringSystem instructions and tone the agent follows.
knowledge_idsarrayKnowledge bases the agent can read from.
model_policyobjectRouting rules — fast vs. reasoning model per task.
Node
const res = await fetch("https://api.genudo.ai/v1/agents", {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${process.env.GENUDO_API_KEY}`,
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    name: "Sales Agent",
    persona: "Friendly, concise. Qualify then book a meeting.",
    knowledge_ids: ["kb_inventory", "kb_pricing"],
    model_policy: { routing: "auto" }
  })
});
const agent = await res.json();

Conversations

Send a message into a conversation and get the agent’s reply, or list history. Conversations are tied to a contact and a channel.

POST/v1/conversations/{id}/messages
JSON · response
{
  "id": "msg_9f2",
  "role": "agent",
  "text": "The villa is available — shall I hold Thursday 2pm?",
  "model": "fast",
  "cost_usd": 0.0021,
  "stage": "qualified"
}

Contacts

Contacts unify a customer across channels. Read a profile with its merged history, attributes and pipeline position.

GET/v1/contacts/{id}
POST/v1/contacts/{id}/attributes

Pipelines

Read pipeline stages and move a contact between them. Stage changes fire whatever actions you’ve configured.

GET/v1/pipelines/{id}
POST/v1/pipelines/{id}/move

Webhooks

Subscribe to events and GenuDo will POST them to your endpoint as they happen — new messages, stage changes, escalations and more. Verify the signature in the X-Genudo-Signature header.

JSON · event
{
  "type": "deal.stage_changed",
  "contact_id": "con_7742",
  "from": "new",
  "to": "qualified",
  "value_usd": 4200
}

MCP

GenuDo speaks the Model Context Protocol. Point Claude Code, Cursor or your own client at the GenuDo MCP server and build, connect knowledge and drive agents from your editor.

shell
# Add GenuDo as an MCP server
mcp add genudo --key $GENUDO_API_KEY
Prefer to stay in your stack? See API & MCP for the full integration guide.
